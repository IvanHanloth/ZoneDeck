# 程序凍結

**程序凍結** 是隱藏視窗後的一項增強功能：在隱藏視窗的同時「暫停」對應的程序，使其停止佔用 CPU（例如暫停背景影片解碼、遊戲算圖等）；復原顯示時自動解除凍結。

相關設定位於設定介面的 **能效控制** 標籤頁。同一標籤頁下還有[效率模式](#效率模式)——一條不停掉程序的省電路子。

::: warning 程序凍結為進階功能
凍結會讓目標程序完全停止執行，其背景工作（如下載、訊息接收）也會暫停。請在瞭解影響後再啟用。

暫停只是讓程序的執行緒不再被排程，它本身不會降低記憶體佔用。想同時降低記憶體佔用，見下文的[降低記憶體佔用](#降低記憶體佔用)。
:::

## 隱藏視窗時凍結程序

這是凍結功能的**總開關**。開啟後，每次隱藏命中的視窗時，ZoneDeck 會暫停對應程序；復原顯示時自動解除凍結，預設使用一般凍結，**不需系統管理員權限**即可對目前使用者的程序生效。

暫停與解除凍結本身需要時間，開啟後可能會造成一定的隱藏／復原延遲。

## 使用增強凍結

一般凍結對某些複雜程式（多程序架構、有算圖子程序等）可能不夠徹底。**增強凍結**改用微軟官方的 `pssuspend64.exe` 工具來暫停程序，效果更強。

啟用增強凍結需要**同時滿足**以下前置條件，否則該選項會被停用：

1. 已開啟「隱藏視窗時凍結程序」總開關；
2. **核心以系統管理員身分執行**（見下文與 [通用設定](/zh-tw/guide/options)）；
3. 程式資料夾下存在 **`pssuspend64.exe`** 檔案。

### 如何取得 pssuspend64.exe

1. 前往微軟 Sysinternals 的 [PSTools 下載頁](https://download.sysinternals.com/files/PSTools.zip)。
2. 解壓縮下載取得的 `PSTools.zip`。
3. 從中找到 **`pssuspend64.exe`**，複製到 ZoneDeck 的**程式安裝根資料夾**。
4. 回到設定介面，按一下「程序凍結」區域的 **重新偵測** 按鈕，讓 ZoneDeck 辨識到該檔案。

增強凍結需呼叫外部程式，同樣會造成一定的隱藏／復原延遲。

## 效率模式

**效率模式**是凍結之外的另一條路：隱藏後不停掉程序，而是把它降為 Windows 的效率模式——繼續執行，但改用能效核心、較低頻率與較低排程優先權，藉此降低耗電與發熱。這正是工作管理員裡那個「效率模式」標記所做的事。

它與凍結**相互獨立**，各有各的開關和作用範圍，可以只開一個，也可以兩個都開。

| | 凍結 | 效率模式 |
| --- | --- | --- |
| 程序狀態 | 完全暫停，不再執行 | 繼續執行，只是變慢 |
| 背景工作（下載、收訊息） | 一併暫停 | 照常進行 |
| 適合 | 可以完全停下的程式 | 不能被停掉的背景程式 |
| 需要系統管理員 | ❌ | ❌ |
| 額外檔案 | 增強凍結需 pssuspend64.exe | 不需要 |

- 預設**關閉**。開啟後每次隱藏都會施加，復原顯示時自動撤銷。
- 不需系統管理員權限即可對目前使用者的程序生效，也不依賴任何外部工具。
- 只有原本是**一般優先權**的程序才會被降低優先權；程序自己設過高／低優先權的，ZoneDeck 只施加能效排程，不動它的優先權。
- **Windows 11 上效果最佳**。Windows 10 也能施加，但只有執行速度節流，沒有完整的 EcoQoS 排程。

## 作用範圍

**作用範圍**決定能效控制涵蓋到哪些程序，預設只管命中視窗所屬的程序本身。凍結與效率模式**各有一套獨立的範圍設定**：

- **凍結及記憶體控制範圍** —— 凍結程序與[降低記憶體佔用](#降低記憶體佔用)共用；
- **效率模式範圍** —— 效率模式單獨使用，與凍結互不影響。

兩者的可選值相同：

| 取值 | 涵蓋 | 適合 |
| --- | --- | --- |
| **僅目標程序** | 命中視窗所屬的程序 | 預設。單程序程式，或只想動主程序 |
| **目標程序及所有子程序** | 上者 ∪ 它的全部後代 | 瀏覽器、Electron 應用這類有算圖／輔助子程序的程式 |
| **同一程式的所有實例** | 系統裡所有**同映像名稱**的程序 | 多開的同一個程式 |

::: tip 「同一程式的所有實例」按檔名比對
它認的是映像名稱（如 `chrome.exe`），不看程序之間的親緣關係，也不區分安裝資料夾——兩個不同位置的同名程式會被一起納入。它**不含**不同名的子程序，那要靠「目標程序及所有子程序」。
:::

::: warning
範圍越大效果越徹底，也越可能影響到你沒打算動的背景工作，並造成更高的隱藏／復原延遲。「目標程序及所有子程序」仍在測試階段。
:::

::: danger 別凍結檔案總管
`explorer.exe` 就是桌面與工作列本身，凍結它會讓整個 Windows 殼層卡住。而且 ZoneDeck 通常由它啟動、是它的子程序——用「目標程序及所有子程序」凍結檔案總管會把 ZoneDeck 一起暫停。

因此 ZoneDeck 的核心與設定程式被**內建**在[白名單](/zh-tw/guide/whitelist)裡，恆不凍結、不可關閉；`explorer.exe` 也預置了一條可刪除的白名單項目。
:::

## 排除特定程式

不想凍結某個程式時，把它加進[白名單](/zh-tw/guide/whitelist)並勾上「略過凍結」即可，不必關掉總開關。該勾選同時也會讓它**略過效率模式**——兩者共用這一條白名單。

## 降低記憶體佔用

凍結本身不省記憶體。開啟 **降低記憶體佔用** 後，ZoneDeck 會在凍結成功之後**清空該程序的工作集**，把它常駐在實體記憶體裡的資料挪到分頁檔，工作管理員的「記憶體」一欄會立刻回落。

::: warning
該選項仍在測試階段。**可能延長復原所需時間，但能一定程度上節省記憶體**——復原時這些資料要從分頁檔讀回來，程序越大、機械硬碟越慢，卡頓越明顯。請在瞭解影響後再啟用。
:::

- 預設**關閉**，且需要先開啟「隱藏視窗時凍結程序」，否則該選項會被灰化。
- 只對**被凍結的**程序生效，與凍結共用「凍結及記憶體控制範圍」（見[作用範圍](#作用範圍)）。還在執行的程序會立刻把資料讀回來，清了也白清。
- 省下的記憶體有一部分並不是直接被回收的：清出去的資料會先進入系統的待命清單，本來在記憶體吃緊時系統也會自己回收。

## 能效統計

能效控制頁最下方有一塊**能效統計**，包含 ZoneDeck 能效控制功能相關的統計：累計凍結了多少程序、施加了多少次效率模式、換出了多少記憶體，以及據此估算的節電量與二氧化碳減排量。

| 指標 | 來源 |
| --- | --- |
| 累計凍結程序 / 累計效率模式 | **實測**。按次計，同一個程序反覆凍結算多次 |
| 累計凍結時長 | **實測**。所有程序的凍結時長之和，三個程序各凍結一小時記三小時；解除凍結時結算 |
| 累計釋放記憶體 | **實測**。清空工作集前後各讀一次工作集，取差值累加 |
| 累計節省電能 | **估算**。按下表的功率乘以凍結 / 效率模式的持續時長 |
| 減少碳排放、等效樹木 | **估算**。由節電量換算 |

估算用的係數：

| 係數 | 取值 | 說明 |
| --- | --- | --- |
| 每個凍結程序省下的功率 | 0.9 W | CPU 側約 0.5 W，折算電源轉換損耗後再計入 GPU、記憶體與 I/O 的連帶停擺 |
| 每個效率模式程序省下的功率 | 0.35 W | 取凍結的四成：程序仍在執行，只是改吃能效核心、降低頻率 |
| 電網碳排放係數 | 0.55 kg CO₂/kWh | 全國電力平均口徑的近似值（2023 年官方發布值為 0.5306） |
| 一棵樹一年的吸收量 | 20 kg CO₂ | 常引用區間為 20~25，此處取下沿 |

點統計區右下角的**重設**可以歸零，歸零不可復原。

## 當機安全

ZoneDeck 會把目前凍結了哪些程序、對哪些程序施加了效率模式記錄到 `recovery.json`。即使核心異常結束，重新啟動後也會接手這些紀錄，如果無法正常接手，核心會**立即解除凍結**先前被暫停的程序，並把效率模式一併撤銷。

前往 [視窗復原與當機自癒](/zh-tw/guide/recovery) 瞭解如何手動復原被凍結的程序。
