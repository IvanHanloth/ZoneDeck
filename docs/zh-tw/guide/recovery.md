# 視窗復原與當機防護

隱藏視窗本質上是把視窗設為不可見。萬一出現意外（忘了快速鍵、核心異常結束等），視窗會不會「永遠消失」？ZoneDeck 從**手動工具**和**自動防線**兩方面確保這不會發生。

## 視窗復原工具

**視窗復原工具**用於找回被誤隱藏、又無法透過快速鍵復原的視窗。

![視窗復原工具](/static/recovery-tool.png)

開啟方式：**設定介面 → 通用設定 → 工具 → 視窗復原工具** 或 **通知區域選單 → 視窗復原工具**。

工具會列出系統中的所有視窗（包括目前不可見的），您只需**勾選**想找回的視窗，按一下「顯示視窗」即可讓它重新顯示。

視窗復原工具也支援將視窗**凍結／解除凍結**，凍結後視窗會被暫停算圖，降低資源消耗。凍結的視窗仍然可透過復原工具找回。

核心執行時，工具的顯示／隱藏操作會交給核心執行：手動隱藏的視窗同樣納入當機復原保護；復原顯示時會連同解除凍結、取消靜音一起完成。核心未執行時工具直接操作視窗。

## 三層防線

ZoneDeck 核心內建了**當機自癒三層防線**，即使程式意外當機也能盡量保證視窗安全。

### 第一層：當機記錄

核心會把關鍵事件與 panic 資訊寫入資料目錄 `logs` 下的記錄檔，按日切割為 `ZoneDeck-YYYY-MM-DD.log`，並依 [記錄檔保留天數](/zh-tw/guide/options) 自動清除過期檔案（設為關閉則不記錄）。記錄多少由 [記錄輸出等級](/zh-tw/guide/options) 決定，預設只記警告與錯誤。**排查問題時先看當天的記錄檔。**

### 第二層：當機復原

每次隱藏視窗時，核心會把「隱藏了哪些視窗、凍結／靜音了哪些程序」寫入 `recovery.json`；正常顯示或結束時刪除該檔案。

核心重新啟動時若發現該檔案仍然存在，表示上次是**異常結束**。此時核心會逐筆核對紀錄裡的視窗

- **全部對得上**：表示你的隱藏意圖沒變，視窗**繼續保持隱藏**，核心接手紀錄，之後照常用快速鍵復原即可。
- **有紀錄對不上**（視窗已關閉、控制代碼被系統回收給了別的視窗，或已經被別的程式顯示出來）：這些紀錄將被捨棄，核心也不會去動那個控制代碼現在指向的視窗，同時記一筆警告記錄並顯示通知告知你。
- **一個視窗都沒接手成功**：表示這輪隱藏已經失效，核心會把還活著的程序**解除凍結、取消靜音、撤銷效率模式**，免得它們一直掛著。

### 第三層：排程工作

[開機自動啟動](/zh-tw/guide/autostart) 若以排程工作方式註冊，會帶有失敗自動重新啟動策略（當機後約 1 分鐘內自動重新啟動，最多 3 次）。核心當機 → 排程工作重新啟動核心 → 重新啟動後由第二層防線接手隱藏紀錄，形成閉環。

## 相關檔案一覽

| 檔案 | 位置 | 作用 |
| --- | --- | --- |
| `config.json` | 資料目錄 | 您的全部設定與綁定 |
| `logs/ZoneDeck-YYYY-MM-DD.log` | 資料目錄 | 當機／事件記錄（按日切割，依保留天數自動清除） |
| `recovery.json` | 資料目錄 | 隱藏狀態快照，用於當機復原（正常結束時刪除） |

::: info 資料目錄在哪
可攜版就在程式資料夾裡，安裝版在 `%APPDATA%\ZoneDeck`（詳見[資料存放位置](/zh-tw/guide/installation#資料存放位置)）。可攜版所在資料夾不可寫入時也會改用 `%APPDATA%\ZoneDeck`。設定介面狀態列的**開啟記錄檔資料夾**按鈕總是開啟目前實際使用的那個資料夾，記錄檔開頭也會記下它。
:::

::: warning 請勿手動刪除執行中的 recovery.json
若在視窗處於隱藏狀態時手動刪除 `recovery.json`，當機復原將失去這次快照。
:::
