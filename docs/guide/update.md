# 检查更新与反馈

配置界面的 **关于与反馈** 标签页汇集了版本信息、检查更新、公告与问题反馈功能。

## 检查更新

打开方式有两种：

1. **托盘菜单** → "关于"。
2. **配置界面** → 关于与反馈页。

检查更新会自动尝试从服务端获取最新版本信息与下载地址：

- 若有新版本，会展示版本号与更新说明，点击即可跳转下载。
- 配置界面也会在启动时**自动**进行一次更新检查。

### 包含预览版

默认只检查**稳定版**。若你希望第一时间体验尚未正式发布的功能，可开启"包含预览版"，让更新检查也纳入预发布（如 `-rc`）版本。

::: warning
预览版可能包含未完全测试的功能，稳定性不如正式版，请谨慎使用。
:::

## 公告

ZoneDeck 支持展示来自服务端的**公告**（如重要更新提示、已知问题说明等）。有新公告时会自动弹出；已读过的公告不会重复打扰。

## 公告与更新说明的语言

公告与更新说明按**当前界面语言**获取：切换界面语言后会立即按新语言重新取一次。某条内容没有对应语言的版本时，显示其默认语言的原文。

## 匿名使用统计

首次启动时 ZoneDeck 会询问是否愿意分享匿名的功能使用情况。**在你做出选择之前，程序不会采集任何统计数据。**

会上报：

- 各项功能开关的开启与关闭情况；
- 规则与白名单数量、正则规则数量、常用热键统计情况；
- 程序版本、语言、运行情况；
- 一个随机生成的不含任何设备特征的匿名标识。

绝不上报：

- 隐藏了哪些窗口、绑定了哪些进程，以及每次隐藏发生在什么时候；
- 窗口标题、进程名、文件路径、正则式本身与反馈正文；
- 姓名、邮箱等能指向你本人的信息。

您随时可以在「通用设置 → 隐私」里退出此功能。关闭后不会再发出任何记录，本机的匿名标识也会一并删除。

## 问题反馈与上报

在"关于与反馈"页可以直接发起**反馈 / 问题上报**，也可以通过 **GitHub 仓库** 提交 [Issue](https://github.com/IvanHanloth/ZoneDeck/issues)

::: tip 反馈时请附上信息
为便于定位问题，反馈时建议附上：
- ZoneDeck 版本号；
- 操作系统版本；
- 复现步骤；
- 相关的 [日志文件](/guide/options#日志保留天数)。
:::

::: warning 请留下联系方式
如果不留联系方式，我们无法直接对反馈进行回复和响应。所以关于功能请求以及 bug 之类的问题，还是推荐将其转换为 Issue。
:::

### 同时转换为 GitHub Issue

反馈框下方提供 **同时转换为 GitHub Issue** 选项（由服务端决定是否开放，未开放时不显示）。勾选后提交，这条反馈会由 Verhub 机器人自动转换为 GitHub Issue：

- **不要求特别的网络环境**，也**不需要登录 GitHub 账号**；
- 选择转换时联系方式**必填，且应填 GitHub 账号**（形如 `@IvanHanloth`）——机器人建好 Issue 后，后续跟进要靠它找到你；
- Issue 创建失败时整条反馈不会被记录，此时请改用下面的手动方式。

你也可以直接前往 GitHub 仓库提交 [Issue](https://github.com/IvanHanloth/ZoneDeck/issues)。仓库提供了 **Bug 报告** 与 **功能建议** 两种 Issue 模板，按模板填写能让维护者更快理解你的问题。
