# 检查更新与反馈

配置界面的 **关于与反馈** 标签页汇集了版本信息、检查更新、公告与问题反馈功能。

## 检查更新

打开方式有两种：

1. **托盘菜单** → "关于"。
2. **配置界面** → 关于与反馈页。

检查更新会自动尝试从服务端获取最新版本信息与下载地址：

- 若有新版本，会展示版本号与更新说明，点击即可跳转下载。
- 配置界面也会在启动时**自动**进行一次更新检查。

### 包含预览版

默认只检查**稳定版**。若你希望第一时间体验尚未正式发布的功能，可开启"包含预览版"，让更新检查也纳入预发布（如 `-rc`）版本。

::: warning
预览版可能包含未完全测试的功能，稳定性不如正式版，请谨慎使用。
:::

## 公告

ZoneDeck 支持展示来自服务端的**公告**（如重要更新提示、已知问题说明等）。有新公告时会自动弹出；已读过的公告不会重复打扰。

## 问题反馈与上报

在"关于与反馈"页可以直接发起**反馈 / 问题上报**，也可以通过 **GitHub 仓库** 提交 [Issue](https://github.com/IvanHanloth/Boss-Key/issues)

::: tip 反馈时请附上信息
为便于定位问题，反馈时建议附上：
- ZoneDeck 版本号；
- 操作系统版本；
- 复现步骤；
- 相关的 [日志文件](/guide/options#日志保留天数)。
:::

::: warning 请留下联系方式
如果不留联系方式，我们无法直接对反馈进行回复和响应。所以关于功能请求以及 bug 之类的问题，还是推荐将其转换为 Issue。
:::

### 同时转换为 GitHub Issue

反馈框下方提供 **同时转换为 GitHub Issue** 选项（由服务端决定是否开放，未开放时不显示）。勾选后提交，这条反馈会由 Verhub 机器人自动转换为 GitHub Issue：

- **不要求特别的网络环境**，也**不需要登录 GitHub 账号**；
- 选择转换时联系方式**必填，且应填 GitHub 账号**（形如 `@IvanHanloth`）——机器人建好 Issue 后，后续跟进要靠它找到你；
- Issue 创建失败时整条反馈不会被记录，此时请改用下面的手动方式。

你也可以直接前往 GitHub 仓库提交 [Issue](https://github.com/IvanHanloth/Boss-Key/issues)。仓库提供了 **Bug 报告** 与 **功能建议** 两种 Issue 模板，按模板填写能让维护者更快理解你的问题。
